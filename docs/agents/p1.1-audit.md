## Notes

1. **The dual-read at `annotator.rb:2071`** (`type_obj.any_sync? \|\| entry.sync`) is the existing transition point — `entry.sync` is already authoritative when set; the type-level fallback covers cases where binding metadata isn't yet flowed. P1.2 should drop the type-level half once P1.3-1.5 ensure `entry.sync` is always populated.

2. **`classify_sync` and the cleanup guards** (`promotion_plan.rb` 692-700, 737) currently take a `ti` (Type). Migration approach: change the call signature to accept the `SymbolEntry` (or a `sync:` kwarg). The callers already have the entry — see `lookup_classifier(name, scope)` paths in `promotion_plan.rb`.

3. **OG classification at `annotator.rb:4377`** has two callers — both pass a bare `type_info`. Migration: pass `SymbolEntry` or a `sync:` kwarg from the caller; in some places this means bubbling the entry up through one call frame.

4. **None of the type-level sites need migration.** They probe literal type structure (struct shape, element shape, primitive-or-Id check). They're unaffected by the binding-metadata move.

5. **Symbol back-references**: most binding-level sites have an Identifier or path to one. AST::Identifier has `symbol` set during annotation. The migration just adds `&.symbol&.sync` paths where they're not already used.

## Test impact prediction

After P1.2, the audit's binding-level sites read from `SymbolEntry#sync` rather than `Type#sync`. Since `entry.sync` is already populated where bindings are declared with `@locked` / `@shared:locked` etc. (lookup at `scope.rb#declare`), the migration should be behavior-preserving for the existing test suite. The behavior **change** comes in P1.3-1.5 when callers' `entry.sync` flows into callees' parameter `entry.sync` — at which point pass-through capability becomes possible.
