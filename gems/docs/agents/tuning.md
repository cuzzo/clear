## 2. High-Noise / Low-Signal Metrics

* **Neglected Updates** (Tier 2)
  * *Behavior*: Pairs all state/global writes across different files and assumes they must be co-updated.
  * *Noise Level*: Extremely high (18,065 findings on [zig](file:///home/yahn/litedb/zig)).
  * *Reason*: The metric lacks context mapping and treats all global/static variables across tests as a single co-written system. Any update to common scheduler configuration fields triggers thousands of false positives.
* **Derived-State Staleness** (Tier 2)
  * *Behavior*: Assumes a derived variable is stale if one of the source variable names is reassigned anywhere downstream.
  * *Noise Level*: High (e.g., 408 findings in [src](file:///home/yahn/litedb/src) and 103 in [zig](file:///home/yahn/litedb/zig)).
  * *Reason*: Reassigning common loop control variables or compiler target variables triggers staleness checks despite proper variable scoping and standard code usage.
* **False Simplicity** (Tier 3)
  * *Behavior*: Flags methods that appear simple but make external calls (mutations, standard I/O, etc.).
  * *Noise Level*: High (e.g., 1,672 findings in [src](file:///home/yahn/litedb/src)).
  * *Reason*: Standard methods delegating work are flagged unconditionally, drowning out actual architectural hotspots.
* **Neglected Path Conditions** (Tier 3)
  * *Behavior*: Suggests missing boolean components in branching guards by matching conditionals across functions.
  * *Noise Level*: High (e.g., 313 findings in [zig](file:///home/yahn/litedb/zig)).
  * *Reason*: Compares distinct, unrelated functions that check the same variables (such as string patterns), flagging missing conditions where no logic relation exists.
* **Broken Protocols** (Tier 3)
  * *Behavior*: Flags when a co-called pair of methods has one call-site without the other.
  * *Noise Level*: High.
  * *Reason*: Frequently triggers on standard utility functions (like cleanup helpers) that do not constitute a strict protocol contract.

## 3. Tooling and Metric Bugs Identified

### Dependency Scan Pollution (Missing Excludes)
* *Bug*: Neither decomplex nor espalier excludes the `vendor` or `target` directories by default. 
* *Impact*: Scanned the entire Ruby bundler dependency path (`vendor/bundle/...`) and Rust build artifacts (`target/release/...`). This resulted in:
  * Giant SARIF reports (~1.6 GB for `nil-kill` decomplex) and markdown files (~12.5 MB).
  * Inflated metric counts and convergence lists dominated by third-party gem paths (e.g., `sorbet-runtime`, `parser`, `prism`, `rbs`).
  * Slow analysis runtimes (several minutes instead of seconds).
* *Fix*: Implement options to only scan git tracked files (`--vcs=git`) and manually exclude build folders (`--exclude **/vendor/**`, `--exclude **/target/**`). Passed `--vcs=git` to [espalier executable](file:///home/yahn/litedb/gems/espalier/exe/espalier).

### Native Traversal Verbose Output
* *Bug*: The native AST analyzer in [profile.rs](file:///home/yahn/litedb/gems/fact-mine/src/profile.rs#L2651) printed `VISIT: type=...` to `stderr` for every traversed syntax node.
* *Impact*: Flooded task logs with over 200,000 lines of trace statements and introduced serious I/O overhead.
* *Fix*: Removed the trace log statement from the `visit` method in [profile.rs](file:///home/yahn/litedb/gems/fact-mine/src/profile.rs).

### Empty Conditional Panic
* *Bug*: `NormalizedExtractor` panicked on `child_node().unwrap()` when parsing specific conditional structures (like empty `if`, `rescue`, or `singleton_class` blocks).
* *Impact*: Panicked when parsing Zig inline structures and normalized fallback structures.
* *Fix*: Implemented safe destructuring instead of `.unwrap()` in [normalized_extractor.rs](file:///home/yahn/litedb/gems/fact-mine/src/syntax/normalized_extractor.rs).

### Class Extraction Mapping Issues
* *Bug*: Espalier treats non-object-oriented files (Zig / C) as pseudo-classes (e.g., reporting files like [atomic-ptr-vopr-test](file:///home/yahn/litedb/zig/atomic-ptr-vopr-test.zig) as a Class).
* *Impact*: Scopes local variables, file constants, or inner struct fields as member attributes of a single top-level class, which creates syntactically misleading architecture maps.
